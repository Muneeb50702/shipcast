# Shipcast

*Stop posting. Start shipping.* A self-hosted social media platform that Claude runs for you. Anyone signs up
at one site, sets up their brand, connects their social accounts and their Claude, and Claude plans, makes and
schedules their content.

Live: **https://social.muhammadmuneeb.tech** (one site, one login).

## How it fits together

```
                       social.muhammadmuneeb.tech  (Cloudflare tunnel)
                        |                         |
          /control/*, /.well-known/oauth-*/control |   everything else
                        v                         v
   Shipcast Control  127.0.0.1:4010        Shipcast Studio  127.0.0.1:4007
   control/app.py                          Postiz v2.25.3 + studio/ brand layer
   - Claude page (inside Studio)           - accounts, workspaces, channels,
   - MCP server /control/mcp (OAuth)         calendar, posting, media
   - brand profile + kits per workspace    - its own MCP (proxied by Control)
   - Platforms: server developer keys  --> /opt/postiz/keys.env
```

- **Studio** is [Postiz](https://github.com/gitroomhq/postiz-app) (AGPL-3.0), rebranded at image build time by
  `studio/`. It never shows the Postiz name, logo or links to its sites.
- **Control** is our own code. It has no accounts of its own: each request's Studio cookies are checked with
  Studio's `/api/user/self`, so the Studio login is the only login. It is multi-tenant: each Studio workspace has
  its own brand profile, kits and connected Claude apps.
- **Claude** connects with one link, `https://social.muhammadmuneeb.tech/control/mcp`. Apps register themselves
  (OAuth DCR) and a workspace admin clicks Allow while logged in. Tools are scoped to that workspace; Studio's own
  MCP tools are proxied as `studio_*` with that workspace's API key, so a customer's Claude only sees their data.
- **Platform developer keys** (YouTube, Meta, LinkedIn, ...) are one set for the whole server, managed on the
  Platforms tab (or Claude's `set_platform_keys` tool) by Studio super admins. Studio lists every platform; one
  connects once its keys are saved (keyless ones such as Bluesky work right away).

## Repo layout -> server

| Repo | On the server |
|---|---|
| `control/app.py`, `control/test_hub.py` | `/opt/hub/` (venv `/opt/hub/.venv`, data `/var/lib/hub/hub.db`) |
| `studio/` | `/opt/postiz/brand/` (build context of the `postiz` service) |
| `deploy/docker-compose.yaml`, `deploy/make-env.sh`, `deploy/dynamicconfig/` | `/opt/postiz/` |
| `deploy/systemd/*` | `/etc/systemd/system/` |
| `deploy/cloudflared/social-hub.yml` | `/etc/cloudflared/` (credentials JSON not in the repo) |

Secrets live only on the server: `/opt/postiz/.env` (generated by `make-env.sh`), `/opt/postiz/keys.env`
(written by Control), `/etc/cloudflared/social-hub.json`, `/var/lib/hub/hub.db`.

## Deploy from scratch (Ubuntu, Docker)

```bash
# Studio
sudo mkdir -p /opt/postiz && sudo cp -r deploy/docker-compose.yaml deploy/dynamicconfig /opt/postiz/
sudo cp -r studio /opt/postiz/brand
sudo useradd --system --home /opt/hub --shell /usr/sbin/nologin hub
sudo bash deploy/make-env.sh social.example.com          # writes .env + empty keys.env
cd /opt/postiz && sudo docker compose build postiz && sudo docker compose up -d

# Control
sudo mkdir -p /opt/hub /var/lib/hub && sudo cp control/app.py control/test_hub.py /opt/hub/
sudo python3 -m venv /opt/hub/.venv && sudo /opt/hub/.venv/bin/pip install -r control/requirements.txt
sudo chown hub:hub /var/lib/hub /opt/postiz/keys.env
sudo cp deploy/systemd/* /etc/systemd/system/ && sudo systemctl daemon-reload
sudo systemctl enable --now social-hub postiz-keys.path

# Cloudflare tunnel (cloudflared tunnel create / route dns), then:
sudo cp deploy/cloudflared/social-hub.yml /etc/cloudflared/ && sudo systemctl enable --now social-hub-tunnel
```

For another domain: set `STUDIO_PUBLIC` for Control (env in the unit) and build Studio with
`--build-arg SHIPCAST_CONTROL=https://<domain>/control`; update the tunnel hostnames.

## Updating

- **Control:** copy `control/app.py`, run `sudo -u hub /opt/hub/.venv/bin/python /opt/hub/test_hub.py`
  (must print `ALL HUB CHECKS PASSED`), then `sudo systemctl restart social-hub`.
- **Studio brand / patches:** edit `studio/`, copy to `/opt/postiz/brand/`, then
  `cd /opt/postiz && sudo docker compose build postiz && sudo docker compose up -d postiz`.
  `brand.js` fails the build if any patch stops matching (e.g. after a Postiz upgrade: bump `FROM` in
  `studio/Dockerfile`). Built chunks are served `no-cache`, so no Cloudflare purge is needed.

## Studio brand layer (`studio/`)

- `rebrand.sh`: renames Postiz to Shipcast in the build, runs `brand.js`, serves `/_next/static` no-cache,
  imports `/shipcast.css` into every stylesheet, then self-checks.
- `brand.js`: purple to orange (hex and Tailwind's compiled rgb values); Settings' CLI/MCP cards and onboarding
  step 2 become the "Connect Claude to Shipcast" guide; the upstream tutorial step is removed; the Agent page
  shows Control (menu item "Claude"); every link to upstream's sites becomes `#shipcast-hidden`.
- `brand.css` (`/shipcast.css`): logos, sign-up panel, hides `#shipcast-hidden` links.
- `public/`, `gen_brand.py`: logo and favicon files and their generator.
